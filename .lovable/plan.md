

## Fix Build Errors and iOS Package Resolution

There are **four distinct issues** causing the build failures and Xcode errors.

---

### Issue 1: Swift Package Manager version conflict (Xcode error)

The error "apple-sign-in depends on capacitor-swift-pm 7.0.0..<8.0.0 and purchases-capacitor depends on capacitor-swift-pm 8.0.0..<9.0.0" means `@capacitor-community/apple-sign-in@7.x` is built for Capacitor 7, but the rest of the project uses Capacitor 8.

**Fix:** Replace `@capacitor-community/apple-sign-in` (stuck on Cap 7) with `@capawesome/capacitor-apple-sign-in` (supports Cap 8). Update `package.json`, the import in any file that uses apple-sign-in, and remove the stale entry from `Package.swift`. After pulling, run `npx cap sync` to regenerate `Package.swift`.

Also, `Package.swift` references two removed packages (`@capacitor-community/background-geolocation` and `@capgo/background-geolocation`). These must be cleaned up — but since `Package.swift` is auto-generated by `npx cap sync`, the fix is to ensure the correct packages are in `package.json` and then re-sync.

---

### Issue 2: `@capgo/background-geolocation` not installed (TS build error)

`src/hooks/useGpsWalk.ts` imports from `@capgo/background-geolocation` but that package was removed from `package.json`. The previous migration to `@capacitor-community/background-geolocation` was reverted in the last diff.

**Fix:** Re-add `@capacitor-community/background-geolocation` to `package.json` and update the import in `useGpsWalk.ts` to use it. The type import should be:
```typescript
import type { BackgroundGeolocationPlugin } from "@capacitor-community/background-geolocation";
```

---

### Issue 3: `@revenuecat/purchases-capacitor` wrong export name (TS build error)

The code imports `{ CapacitorPurchases }` but the package exports `Purchases` as default, plus named exports like `configure`, `logIn`, etc. — not `CapacitorPurchases`.

**Fix:** Update `src/lib/iap-service.ts` to use the correct named exports from `@revenuecat/purchases-capacitor`:
```typescript
import { Purchases } from "@revenuecat/purchases-capacitor";
```
Then replace all `CapacitorPurchases.xxx()` calls with `Purchases.xxx()` calls. The API also changed — `setup()` is now `configure()`.

---

### Issue 4: Edge functions using `npm:@supabase/supabase-js@2.57.2` (Deno build error)

Four edge functions use `npm:@supabase/supabase-js@2.57.2` which Deno can't resolve in the sandbox. The other functions use `https://esm.sh/@supabase/supabase-js@2.49.1` which works fine.

**Fix:** Change the import in these 4 files to use the esm.sh URL:
- `supabase/functions/create-checkout/index.ts`
- `supabase/functions/create-portal-session/index.ts`
- `supabase/functions/stripe-webhook/index.ts`
- `supabase/functions/verify-payment/index.ts`
- `supabase/functions/sync-iap-subscription/index.ts`

Also fix the `getClaims` calls in 4 edge functions — replace with `getUser(token)` which is the correct method for the supabase-js v2 SDK.

---

### Issue 5: `getClaims` does not exist on `SupabaseAuthClient` (TS error in edge functions)

Six edge functions call `userClient.auth.getClaims(token)` which doesn't exist in supabase-js v2.

**Fix:** Replace with:
```typescript
const { data: { user }, error: userError } = await userClient.auth.getUser(token);
if (userError || !user) { /* return 401 */ }
const userId = user.id;
```

Affected files:
- `generate-certificate/index.ts`
- `generate-stamp-image/index.ts`
- `send-stamp-email/index.ts`
- `send-certificate-email/index.ts`
- `generate-challenge-images/index.ts`
- `validate-challenge/index.ts`

After pulling these changes locally:
1. Run `npm install`
2. Run `npx cap sync` — this regenerates `Package.swift` with correct dependencies
3. Clean Xcode build folder (Product → Clean Build Folder)
4. Build again in Xcode
